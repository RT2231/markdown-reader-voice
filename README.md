# 読み上げリーダー (Markdown Voice Reader)

<a href="https://tsukutta.app/apps/7c82391d-9226-45da-a45f-db4ea8504254"><img src="https://tsukutta.app/api/badge/7c82391d-9226-45da-a45f-db4ea8504254?lang=ja" alt="Tsukuttaに掲載中" width="200" height="40"></a>

Markdown ファイルを読み込み、表示しながら音声で読み上げる単一HTMLのWebアプリです。
`index.html` を GitHub Pages / Cloudflare Pages などにそのまま置くだけで動作します（ビルド不要）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（これ1ファイルで完結。静的ホスティングにそのまま配置） |
| `worker.js` | ElevenLabsをブラウザに直接鍵を渡さず使うためのCloudflare Workerプロキシ（**ElevenLabsを使う場合のみ必要**） |

## セットアップ

### 1. アプリ本体（必須）

`index.html` を GitHub Pages などにアップロードするだけで、**ブラウザ標準音声（SpeechSynthesis）はすぐ使えます**。追加設定は不要です。

### 2. ElevenLabsを使う場合（任意・運営者が1回だけ行う作業）

このアプリのElevenLabs機能は、**運営者（あなた）が1つだけWorkerをデプロイし、全利用者がそれを共有する**構成です。利用者側でWorker URLなどを入力する項目はありません。手順はすべてCloudflareダッシュボードで完結し、CLIは使いません。

1. Cloudflareダッシュボード → **Workers & Pages** → **Workers を作成する**
2. 名前を付けて作成（例: `markdown-reader-voice-api`）
3. エディタを開き、`worker.js` の中身を全部貼り付けて **保存してデプロイ**
4. Workerの **設定 → 変数とシークレット** で以下を追加
   - 名前: `ELEVENLABS_API_KEY` / 値: あなたのElevenLabs APIキー / 種別: **シークレット**
   - （推奨）名前: `ALLOWED_ORIGIN` / 値: アプリを公開しているオリジン（例: `https://your-name.github.io`）— 未設定時は全オリジンからのブラウザ経由リクエストを許可
5. Workerの **設定 → トリガー** に表示されるURL（`https://xxxx.workers.dev`）をコピー
6. `index.html` を開き、冒頭付近にある次の行にコピーしたURLを貼り付けてから配信してください（利用者が入力する項目ではなく、アプリ側に固定で埋め込む値です）。
   ```js
   const WORKER_URL = ""; // ここに https://xxxx.workers.dev を入力
   ```
7. 保存して配信すると、全利用者の設定画面でElevenLabsエンジンが自動的に選択可能になり、音声一覧も自動取得されます。

`WORKER_URL` が空のままの場合、設定画面のElevenLabsカードは自動的に無効表示になり、ブラウザ標準音声のみが使える状態で問題なく動作します。

KV・D1・Pagesは今回のWorkerでは使用していません（Worker単体で完結します）。もし将来的に音声キャッシュ用にKVを使う、Pagesでホストするなどの拡張をしたい場合は、その時に改めてご相談します。

## 主な機能

- Markdownの読み込み: ファイル選択 / ドラッグ&ドロップ / URL指定（直接fetch → 失敗時は共有Worker経由でCORS回避）
- 表示: 見出し・段落・強調・打ち消し線・引用・リスト・番号付きリスト・チェックリスト・表・コードブロック・インラインコード・数式（KaTeX）・Mermaid図・生HTMLタグに対応
- サイドバーに見出し一覧、クリックでジャンプ、読み上げ中の見出しをハイライト
- 読み上げ中の文章を1文単位でハイライト
- 読み上げエンジン: ブラウザ標準（SpeechSynthesis） / ElevenLabs（運営者が用意した共有サーバー経由）をワンタッチで切替
- 読み方の詳細設定（見出し・リスト・引用・強調・コードブロック・URL・画像altそれぞれの読み方）
- 再生・一時停止・停止・前/次の文へ移動・シークバー・速度・ピッチ・音量・音声の変更
- **本文中の好きな文をクリックすると、そこから読み上げが始まる**
- **続きから再生（しおり）**: 読んでいる位置を自動保存し、同じドキュメントを再度開くと「続きから再生」できる
- **文字サイズ・行間・本文幅の調整**
- **スリープタイマー**（5〜60分後に自動で一時停止）
- ダークモード
- 音声ファイル保存（ElevenLabsエンジンのみ、MP3 / WAV）
- 設定（音声・速度・ピッチ・音量・読み方設定・エンジン・ダークモード）はLocalStorageに自動保存

## ご質問への回答

### バックグラウンド再生について

- **ElevenLabsエンジン**は実音声ファイルを `<audio>` 要素で再生しており、Media Session API に対応しています。画面ロック中や他アプリ表示中でも再生が継続しやすく、ロック画面・通知エリアからの再生/一時停止/次へ/前へ/シーク操作にも対応します。**確実にバックグラウンド再生させたい場合はこちらを推奨します。**
- **ブラウザ標準エンジン（SpeechSynthesis）**は仕組み上、タブがバックグラウンドになったりOSの制約（特にiOS Safari）がかかると、ブラウザ側が音声合成を強制的に一時停止することがあります。これはWebアプリ側からは完全には制御できないブラウザ/OSの仕様です。本アプリでは以下の緩和策を実装しています。
  - 再生中は定期的に `speechSynthesis.resume()` を呼び、意図せず一時停止した場合に自動再開を試みる（Chromeなどで知られる自動停止バグへの対策）
  - タブがバックグラウンドに切り替わった瞬間にも再開を試みる
  - Media Sessionにメタデータと操作ハンドラを登録し、対応環境ではロック画面上の操作を受け付ける
  
  ただし完全な保証はできません。長時間・確実なバックグラウンド再生が必要な場合は、ElevenLabsエンジンの利用をおすすめします。

### シークバーの不安定な挙動について

原因は一般的に「ドラッグ中に発生する `input` イベントのたびに読み上げエンジンへ再生成/再開要求を送ってしまい、非同期処理同士が競合すること」にあります。本アプリでは以下のように対処しています。

1. ドラッグ中（`input` イベント）は **見た目の位置と時刻表示のみ更新**し、エンジンへは一切指示を送らない
2. 指を離した／マウスを離した瞬間（`change` / `pointerup` / `touchend` / キーボード操作後）に**一度だけ**実際のシーク処理を実行
3. シーク実行時は内部の「再生トークン」をインクリメントし、それ以前に発行された読み上げ完了イベント（`onend`・`timeupdate`など）が**古いトークンだったら黙って無視する**ようにして、過去の再生指示が新しい位置の再生を妨げないようにしている
4. ElevenLabsエンジンでは実際の音声ファイルの `currentTime` に対して直接シークするため秒単位で正確に移動できます
5. ブラウザ標準エンジンはWeb Speech APIの仕様上、発話の途中から再生を再開する機能がないため、シークは「最も近い文の先頭」への移動になります（段落やページ全体のジャンプではなく、文単位の精度です）

## セキュリティについて

このアプリは**全利用者が同じ1つのWorkerを共有する**構成です。その前提での注意点です。

- ElevenLabsのAPIキーはWorker内のシークレットにのみ保存され、ブラウザ・LocalStorageには一切保存されません。
- `/api/fetch-url`（URL読み込み用プロキシ）は、`localhost`・プライベートIP（社内ネットワークなど）・クラウドのメタデータエンドポイント宛のリクエストを拒否します（SSRF対策）。
- すべての外部リクエストにタイムアウト（10秒）と取得サイズの上限（2MB）を設けています。
- 読み込んだMarkdown内の生HTMLはDOMPurifyでサニタイズし、`<script>`・`<iframe>`・`<form>`・インラインイベントハンドラ等を除去しています。`target="_blank"`付きリンクには自動的に`rel="noopener noreferrer"`を付与します。
- **⚠️ レート制限は実装していません。** `ALLOWED_ORIGIN` はブラウザ経由のリクエストを絞り込みますが、curlなどでWorker URLへ直接アクセスされることまでは防げません。Worker URLが広く知られると、あなたのElevenLabs APIキーの利用量（＝費用）が想定より増える可能性があります。運用にあたっては、ElevenLabs側のダッシュボードで**利用量アラート・上限（Usage limit）を設定しておくこと**を強く推奨します。将来的にレート制限を追加したくなった場合は、Cloudflare KVを使った簡易的な仕組みをいつでも追加できます。

## 既知の制限

- 音声ファイルの保存（ダウンロード）はElevenLabsエンジンのみ対応です。ブラウザ標準音声はブラウザが音声データを外部に渡す手段を提供していないため、技術的に保存できません。
- ElevenLabsのAPI利用量に応じて費用が発生します（Worker側のAPIキー所有者に課金されます）。
- SpeechSynthesisのバックグラウンド動作はブラウザ・OS依存です（上記参照）。
